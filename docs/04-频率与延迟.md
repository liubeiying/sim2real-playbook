# 控制频率与通信延迟

## 症状

- 真机"发抖"、动作不连贯
- 指令明明发了，动作慢半拍
- 仿真里平滑的轨迹，真机上一段一段的

## 根因：两条链路的频率差

```
下行指令流：推理节点 50 Hz → 安全限幅 → DDS → 底层总线 1000 Hz → 电机
上行状态流：编码器/IMU 采样 → 时序对齐与滤波 → 构造观测 → 策略
```

**50 Hz 与 1000 Hz 之间存在 20 倍频率差。** 策略每 20 ms 给一个目标位，底层每 1 ms 执行一次伺服——中间必须有插值与相位对齐，否则机器人会"一顿一顿"。

## 排查清单

- [ ] 策略推理频率实际是多少（实测，不要信配置）
- [ ] 底层总线周期是多少
- [ ] 中间是否做了插值
- [ ] 端到端延迟实测（发布时刻 → 电机响应时刻）
- [ ] DDS QoS 配置是否匹配（QoS 不匹配会导致收不到且不报错）

## DDS 一个特别阴的坑

ROS 2 里 **发布端与订阅端 QoS 不匹配时，消息收不到且不抛异常**。
表现：`topic list` 看得到话题，`echo` 就是没数据。

```bash
# 查 QoS（可靠/尽力、深度、持久性）
ros2 topic info /your_topic --verbose
```

> 我在这上面耗过时间。现在我的习惯是：**链路不通先查 QoS，再查代码。**
