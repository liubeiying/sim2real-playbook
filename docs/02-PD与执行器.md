# PD 增益与执行器建模

## 症状

- 动作幅度整体偏大或偏小（不是局部问题）
- 机器人软绵绵，或者过硬
- 仿真里力气刚好，真机上使不上劲

## 查什么

| 项 | 检查内容 |
|---|---|
| 刚度 Kp / 阻尼 Kd | 数值本身 |
| **单位与量纲** | 两个引擎是否同一套单位 |
| 控制类型 | 位置控制 / 力矩控制，两者 PD 含义不同 |
| 力矩上限 | 是否被截断 |
| 摩擦与阻尼模型 | 关节摩擦建模差异 |

## 单位问题是重灾区

同一个"Kp = 100"，在不同框架里可能意味着完全不同的物理量。**不要只看数字，要确认它乘在什么量上。**

单位不一致的案例待补。

## 执行器建模差异

- 力矩上限设置不同 → 真机使不上劲
- 关节摩擦未建模 → 仿真里过于顺滑
- 忽略电机动态（一阶滞后）→ 高速运动时相位偏差

## 排查方法

1. 给一个阶跃目标位，记录两个引擎的响应曲线
2. 对比上升时间、超调、稳态误差
3. 差异全部归因到 Kp / Kd / 力矩上限 / 摩擦这四项

## 一点体会

PD 参数不是"调出来好看"就行，它必须和真机的物理单位对齐。我现在的习惯是把 PD 参数和单位说明一起写进配置文件注释里，避免下次复现时再踩一遍——尤其是隔了几个月回来改代码的时候。
