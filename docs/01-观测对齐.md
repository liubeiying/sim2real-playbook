## 症状

策略在 Isaac Gym 里走得很好，换到 MuJoCo 直接摔倒，或者动作完全乱套，**像在执行随机策略**。

## 为什么这是第一位要查的

策略网络是一个固定的函数映射：**观测向量 → 动作**。

如果第 3 位本来是"左髋关节角"，你喂进去的却是"躯干角速度"，网络照样会输出一个看起来合理的动作——只是这个动作对应的是完全错误的输入。

**表现不是报错，而是一脸无辜地摔倒。** 这是它最难查的原因，也是我把它排在第一位的原因。

3. 逐位比对，打印所有差值超过阈值的位置
4. 定位到具体位次，回去核对观测构造函数

## 常见错位来源

| 来源 | 说明 |
|---|---|
| 拼接顺序 | 两个引擎的观测 concatenation 顺序不同 |
| 坐标系 | 四元数顺序（wxyz vs xyzw）、世界系 vs 机体系 |
| 归一化 | 一个引擎做了 clip / scale，另一个没有 |
| 历史帧 | 是否堆叠历史观测、堆叠顺序 |

## 我的做法

把观测顺序检查写成脚本，每次换引擎、每次改观测构造都跑一遍。

这是我踩完之后固化下来的硬规则：靠记忆保证的东西一定会出错，靠脚本保证的才不会。
