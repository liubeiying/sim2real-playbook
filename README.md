## 核心方法：逐位比对，不靠肉眼看行为

我踩过最久的一个坑，就是因为"看起来差不多"而没去对数字。正确做法是写脚本逐位比对两个引擎的观测值，差异一目了然。

```python
# 思路示例
for i, (a, b) in enumerate(zip(obs_gym, obs_mujoco)):
    if abs(a - b) > 1e-3:
        print(f"第 {i} 位不一致: gym={a:.4f} mujoco={b:.4f}")
```

我自己的对比脚本在补录中，思路已经能直接用。

## 真机部署的四道门禁

```
零力矩 → 调试模式 → 悬挂测试 → 落地行走
```

1. **零力矩**：确认所有电机力矩归零，机器人不自发运动
2. **调试模式**：低速小幅度验证指令链路通
3. **悬挂测试**：吊起来跑，摔倒也不伤人伤机
4. **落地行走**：最后才放开

绝不跳步。人形机器人一次误下发的代价，远超多花的两小时。

## 安全设计

- [ ] 动作下发前二次确认
- [ ] 关节角度 / 速度超限**直接拒绝输出**（不是弹警告，更不是放大）
- [ ] 策略输出先过限幅层再进底层总线
- [ ] 调试等级分级配置，禁止一步到位

安全规则只有代码化才可审计。写在文档里等于没有——我吃过这个亏。
